<SC>
`import` 语句将另一个文件中导出的声明带入导入文件的命名空间。 \{#sls.import.semantics}

<OnlyInSC>
被导入的源文件本身应符合本规范。 \{#sls.import.subset}
</OnlyInSC>

## 位置

`import` 语句出现在 `.slint` 源文件的顶层，
与[组件定义](../file-structure/#sls.file.component.definition-forms)和[导出](../exports/)交错。 \{#sls.import.placement}

## 具名导入

<OnlyInSC>
每条 import 语句都是具名导入。 \{#sls.import.named-only}
</OnlyInSC>

具名导入具有以下形式： \{#sls.import.forms}

```slint no-test
import { Item, ... } from "path";
```

由花括号界定的列表包含一个或多个以逗号分隔的*导入项*。
允许尾随逗号。 \{#sls.import.list}

导入项可以是： \{#sls.import.item}

- 单个[标识符](../lexical-structure/#sls.lex.identifier.classes) `Name`，或
- `Name as Other` 形式的改名。

裸标识符 `Name` 将导入文件中对应的导出名字以相同的名字带入当前文件的命名空间。 \{#sls.import.same-name}

改名 `Name as Other` 将对应的导出名字仅以名字 `Other` 带入当前文件的命名空间。
原始名字 `Name` 不会被引入。 \{#sls.import.rename}

`as` 左侧的名字必须由被导入文件导出。 \{#sls.import.left-must-exist}

同一源文件中的两个导入项不能引入相同的名字。 \{#sls.import.no-clash}

<OnlyInSC>
被导入的名字指向一个组件。 \{#sls.import.kinds}
</OnlyInSC>
</SC>

被导入的名字指向组件、结构体、枚举或全局对象。

## 导入路径

导入路径是双引号字符串字面量。 \{#sls.import.path-literal}

<OnlyInSC>
该路径相对于导入源文件所在目录解析。 \{#sls.import.path-relative}
</OnlyInSC>

引号之间的字符按原样处理：不解析转义序列。
`/` 和 `\` 都是目录分隔符，
因此反斜杠用于分隔目录，而不是转义下一个字符。 \{#sls.import.path-verbatim}

</SC>

如果路径以字符 `@` 开头，它就是*库导入*：
路径的其余部分相对于构建系统中配置的[组件库](../../../guide/language/coding/file/#component-libraries)解析。

否则，路径首先相对于导入源文件所在目录解析，
然后相对于编译器配置的包含路径解析。
使用该搜索顺序中的第一个匹配项。

<SC>
被引用的文件必须存在。 \{#sls.import.path-must-exist}
</SC>

## 文件导入

不带导入列表的 import 语句使被引用的文件对编译器可用： \{#sls.import.file}

```slint no-test
import "./NotoSans-Regular.ttf";
```

导入字体文件（`.ttf` 或 `.otf`）会注册该字体以供应用中使用；
参见[字体](../../../guide/development/fonts/)。 \{#sls.import.file-font}

<a id="re-exports"></a>

## 重新导出

带 `from` 子句的 [export](../exports/) 语句一步导入并再次导出声明： \{#sls.export.reexport}

```slint no-test
export { Item, ... } from "path";
export * from "path";
```

`*` 形式导出被引用文件导出的每一条声明。
它最多每个文件出现一次。
该路径像任何其他[导入路径](#import-paths)一样解析。 \{#sls.export.reexport-all}
