实验性功能不属于稳定的 Slint，可能会随时发生变化。
其目的是让我们在正式承诺之前尝试新想法并收集反馈。

实验性功能需要主动启用。
启用方式取决于你使用的语言和工具。

## 启用实验性功能

<Tabs syncKey="dev-language">
  <TabItem label="Rust" icon="seti:rust">
  在构建应用时设置 `SLINT_ENABLE_EXPERIMENTAL_FEATURES` 环境变量：

```bash
SLINT_ENABLE_EXPERIMENTAL_FEATURES=1 cargo build
```

  </TabItem>
  <TabItem label="C++" icon="seti:cpp">
  在配置 Slint 时向 CMake 传递 `-DSLINT_FEATURE_EXPERIMENTAL=ON` 标志：

```bash
cmake -DSLINT_FEATURE_EXPERIMENTAL=ON ..
```

这只在从源码构建 Slint 时有效。
预构建的 C++ 包不提供实验性功能。

  </TabItem>
  <TabItem label="NodeJS" icon="node">
  在运行应用时设置 `SLINT_ENABLE_EXPERIMENTAL_FEATURES` 环境变量，因为 Slint 编译器在加载时运行：

```bash
SLINT_ENABLE_EXPERIMENTAL_FEATURES=1 node app.js
```

  </TabItem>
  <TabItem label="Python" icon="seti:python">
  在运行应用时设置 `SLINT_ENABLE_EXPERIMENTAL_FEATURES` 环境变量，因为 Slint 编译器在加载时运行：

```bash
SLINT_ENABLE_EXPERIMENTAL_FEATURES=1 python app.py
```

  </TabItem>
</Tabs>

## 工具

`SLINT_ENABLE_EXPERIMENTAL_FEATURES` 变量还会在 `slint-viewer` 中启用实验性功能。
`slint-lsp` 在以 `SLINT_ENABLE_EXPERIMENTAL_FEATURES=1` 启动时，或者在编辑器设置 `experimental` 工作区选项时，会启用实验性功能。

## SlintPad

在 SlintPad URL 后添加 `?EXPERIMENTAL=1`：[snapshots.slint.com/master/editor/?EXPERIMENTAL=1](https://snapshots.slint.com/master/editor/?EXPERIMENTAL=1)。
